Enterprise Multimodal Transformation Engine with Deterministic Factual Grounding & Targeted Self-Healing

1. System Overview & Problem Statement

In enterprise, government, and institutional environments, raw source information (audit reports, incident logs, policy memos) must be communicated across conflicting stakeholder domains: C-Suite leaders require concise executive impact; engineering leads require root-cause advisories; marketing teams require social summaries; visual teams require presentations and video storyboards. Traditional generative AI workflows suffer from factual drift, ungrounded extrapolations, contradictory statistics across formats, and excessive regeneration latency caused by uncoordinated sequential prompts.

The Architecture: The platform solves this through a three-tier architecture: an upstream Canonical Content Model (CCM) extracting ground-truth facts, a Consolidated Generation Engine producing up to 7 formats simultaneously via Google Gemini (gemini-3.5-flash-lite) in ~7s, and an application-side Deterministic Grounding Engine that verifies factual integrity and triggers isolated Targeted Self-Healing without regenerating valid outputs.

3. Major Architectural Subsystems

🖥️ Presentation Layer

React 18 + Vite SPA. Manages 5-stage state pipeline. Custom visualizers: slide deck carousel with speaker notes, KPI card layouts, 3-column video storyboards, and inline single-format refinement drawers.

🛡️ API Gateway Layer

FastAPI modular monolith. Enforces Pydantic v2 schemas (TransformRequest, RefineRequest), 35MB payload limit middleware, and in-memory sliding-window IP rate limiter (60 req/min).

⚙️ Grounding & Healing

Application-side deterministic validation. Decoupled from LLM: uses suffix-stripping morphological stemming, currency normalizers, multi-scale windows, and single-format recovery loops.

4. Canonical Content Model (CCM) — Upstream Ground Truth

Defined in transform_schema.py and constructed deterministically in transform_service.py before generation. Captures verbatim source truth to prevent hallucination at prompt inception and act as reference oracle during audit:

  • Claims: Substantive factual assertions split along sentence boundaries.
  • Metrics & Currencies: Normalized numbers, percentages, multipliers, and financial amounts (e.g., $12M = 12 million dollars).
  • Dates & Entities: Temporal anchors (quarters, years, calendar dates) and compound enterprise/platform nouns.
  • Events & Standards: Real-world corporate milestones (acquisitions, certifications) and benchmarks (SOC 2, ISO 27001).
  • Traceability: Retains source_reference and raw source_text directly for end-to-end auditability.

5. Consolidated AI Generation Architecture

Instead of dispatching 7 separate LLM calls (25–35s latency and cross-format divergence), the system executes a single consolidated Gemini request. Formulates a unified prompt embedding the source, CCM context, and strict JSON schema blueprints for all requested formats. Configured to gemini-3.5-flash-lite with temperature=0.3, max_output_tokens=8192, and response_mime_type="application/json". Completes all 7 formats simultaneously in ~6.94 seconds (~0.99s per format).

Deterministic Validation, Targeted Recovery, Security Controls & Empirical Verification

7. Deterministic Factual Grounding Engine

Because LLMs produce plausible but fabricated statistics and events, the architecture decouples generation from validation. Validation is executed deterministically on the application server without circular LLM self-evaluation:

  • Scaffolding Exclusion: Strips non-factual formatting labels (Slide 1:, Scene 2:, Narration:) before verification to eliminate false-positive flags.
  • Metric & Currency Normalization: Converts varied monetary strings into normalized (currency, float) tuples. Rejects ungrounded numerical deviations (e.g., claiming 15% when source states 12%).
  • Event & Relation Verification: Checks binding business milestones (acquisitions, certifications) against FACTUAL_EVENT_PATTERNS.
  • Morphological Suffix-Stripping Stemmer: Resolves grammatical inflections (reduces = reducing) to prevent false rejections of valid paraphrasing.
  • Multi-Scale Source Window Containment: Validates candidate propositions against sentence windows and 3-sentence sliding chunks.
  • Cross-Format Consistency Matrix: Compares extracted metrics across all 7 formats to detect cross-deliverable factual contradictions.

8. Composite Quality Gate & Scoring Formula

Deterministic Formula: Score = 0.35 × Grounding + 0.25 × Structure + 0.25 × Consistency + 0.15 × Compliance Gate Threshold: ≥ 0.80

Weights: Grounding (0.35, -0.35 per unverified metric, -0.30 per unsupported event); Structure (0.25, format compliance); Consistency (0.25, -0.20 per cross-format contradiction); Compliance (0.15, audience/tone adherence). The Quality Gate passes if Score ≥ 0.80 and zero fatal structural or grounding defects exist.

9. Targeted Self-Healing / Single-Format Recovery

When an output format fails validation, the system executes an isolated recovery workflow rather than restarting the entire generation pipeline:

[Outputs Generated] ──► [Grounding Engine] ──► Format Fails (e.g. Advisory metric error) │ ▼ [Valid Formats Preserved] ◄── [Re-Validated] ◄── [Targeted LLM Call] ◄── [Negative Prompt with Defect Report]

targeted_recover_missing_output() isolates *only* the failing format, constructs a targeted prompt containing the failed draft, itemized defect list, and explicit negative constraints (e.g., *"Eliminate unverified metric 15%; ground all claims in source"*), dispatches a single Gemini request, re-validates the output, and merges it back into the result set.

10. Selective Single-Output Refinement (`/refine`)

Users can iteratively revise individual outputs without causing side-effects on sibling deliverables. The POST /refine endpoint takes user instructions and current text, refines only that target format via Gemini in ~1.89 seconds, re-runs factual grounding, and updates *only* that format key in the frontend React state while keeping all other deliverables frozen.

11. Security, Isolation & Reliability Controls

🔒 Secret & API Key Isolation

Server-side .env boundary. Zero keys exposed to client bundles or tracked in git (git grep "AIzaSy" returns 0). Client communicates strictly via schema-validated API gateway.

🛡️ DoS & Payload Defense

Starlette middleware drops requests > 35 MB before memory buffering (HTTP 413). Sliding-window IP rate limiter enforces 60 req/min limit on transform routes (HTTP 429).

📁 In-Memory File Processing

Documents and media parsed purely in RAM streams (io.BytesIO). Zero disk persistence, eliminating path traversal (../) and arbitrary script execution risks.

⚡ Deterministic Mock Fallback

Setting USE_MOCK=true triggers offline deterministic mock generation, allowing complete end-to-end evaluation without API quota or network access.

14. Top Architectural Differentiators (vs Naive Wrappers)

  • Upstream Canonical Content Model (CCM): Factual extraction anchors generation before LLM synthesis, preventing initial hallucinations.
  • Consolidated Single-Pass Generation (~7s for 7 Formats): Reduces API calls from 7 to 1, eliminating latency overhead and cross-format metric divergence.
  • Application-Side Deterministic Grounding: Replaces unreliable, circular LLM self-grading with algorithmic stemming, currency normalization, and multi-scale windowing.
  • Targeted Self-Healing Loop: Heals individual failing formats with negative constraint injection without regenerating valid deliverables.
  • State-Isolated Single-Output Refinement: Modifies only the selected format in ~1.9s, preserving all sibling outputs in their validated state.
